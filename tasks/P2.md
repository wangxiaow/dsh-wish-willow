## P2-A：独立 Reviewer（代码完成，运行未验证）

- [Reviewer](<../packages/p1/src/reviewer.js>) 使用新的 `wish-review-*` Session；不传 seed/parentSession/parentAgent、不 fork 编码会话；允许使用同一默认模型。
- Host 在 Coder idle、可靠 Session 结果检查并 dispose 后，组装实际候选/基线源码、真实差异、产品契约、测试脚本/命令、执行 Evidence 与 P1 完整性报告。Coder 自述明确为 claim。
- 权限 `read-only` / `never`；先对全局工具只允许已核实的 `read`，再以 scoped `read` **遮蔽通用文件读取**，仅接受材料 ID 和有限字符分页；另有一次结构化提交工具。同步白名单 guard 独立拒绝 Shell、写入、网络、其他 Agent、审批/释放、越界和权限扩张。
- 报告含候选/变更/版本/构建/快照/材料/契约绑定、检查项、必须处理/建议问题、材料 ID 与定位、风险和 PASS/FAIL/BLOCKED/UNVERIFIED。
- PASS 需要实际成功读回、完整模型可见正文及 Session 中对应的持久 tool/result 正文，必要材料完整覆盖、必要检查有实际引用、正常 turn/end、Session flush 与合法报告；未知、缺证据、工具/模型错误、取消、预算耗尽不放行。
- 每次最多 20 步、300 秒、120 工具调用；不自动重试。同一候选最多一次用户显式重审，追加新 Session/结果，保留第一次失败。

## P2-B：Host 状态门禁与最小 UI（代码完成，运行未验证）

- [质量策略](<../packages/p1/src/quality-gate.js>)：低风险必须有可比较基线，差异限 README/docs 非执行说明且入口/验证命令未变；首发、功能/测试/配置/入口等默认中风险；重大决策、敏感数据/权限、破坏性操作或外部发布标记为高风险。规则保守、可解释，不是通用扫描器。
- Reviewer 只能提高风险，不能降低 Host 下限。低/中风险须 PASS；高风险还须明确用户批准，绑定候选、最新审查、完整 binding、风险事项和 `local-delivery-only` 范围。批准不授予删除、改权限或公网发布权。
- [状态层](<../packages/p1/src/state.js>) 的 `releaseCandidate` 是唯一新增 Release 入口；泛用 mutate 即使声称 runtime 也没有一次性文件复核许可，不能追加 Release。释放前复核当前/基线文件、材料、完整性、报告哈希与关联，再 revision CAS 原子追加；复核/提交期间的明确取消阻断释放，保留已有审查记录。
- Product State 可选增加 `quality`（候选、尝试、终结报告、批准、门禁），Release 可选 `qualityGateId`；复用 Artifact 新种类 `review-materials`/`review-report`。原 Build/Evidence/Artifact 事实和 Release、质量历史不可覆盖。材料 Artifact 绑定候选，不回写已经记录的 Build。
- 高风险待批准候选持久化，重开 Host 不重跑 Coder/Reviewer；中断的进行中审查追加 BLOCKED，等待用户选择，不自动恢复模型调用。
- [RPC](<../packages/p1/src/host.js>)：`approveCandidate`、`reReview`、`resumeCandidate`；继续交付只检查原候选，不编码、不调模型。
- [统一 UI](<../client.js>)：风险、当前 Reviewer/Host 判定、检查/问题、读证据、历史和候选绑定的批准/拒绝/重审/继续；当前版本、当前测试及当前失败不会被旧 Release/旧成功测试掩盖。仍为一个 Bundle、一个 Client、原有 Domain。

## P2-C：有限测试与验收准备（代码完成，执行未授权）

| 有限类别 | 准备的验证代码 |
|---|---|
| 合法 PASS 恰好释放一次；普通 mutate 不能绕过 | [状态门禁测试](<../tests/p2-quality-gate.test.mjs>) |
| exit 0 仍违反明确需求，独立读源码/弱测试后 FAIL | [Reviewer 测试](<../tests/p2-reviewer.test.mjs>) |
| 缺读、缺相关测试、错 binding、报告畸形不 PASS | 同上及状态门禁测试 |
| 高风险缺批准、拒绝、过期/错范围、合法批准 | 状态门禁测试；真实 storage 重开使用脚本化 Agent |
| 创建失败、模型错误、实际取消、步数/时间耗尽 | Reviewer 测试（模型/命令 DTO 全部脚本化） |
| Shell/写/网络/其他 Agent/审批/释放/越界被工具层拒绝 | Reviewer 测试 |
| 哈希变更、旧报告、重启、并发审批无错误释放 | 两组测试；对隔离 fixture 故意篡改源码 |
| 旧 Product State/Release 不补造质量数据、不 eager rewrite | 状态门禁测试；既有兼容/升级断言保留 |
| 旧成功交付不能掩盖当前 FAIL/失败测试/当前版本 | [UI 测试](<../tests/p2-client.test.mjs>) |

脚本化 Reviewer 必须显式提供；缺少 fixture 会 BLOCKED，不能默许 Coder 自述为 PASS。既有 P1 正例仅新增明确标记的 Reviewer plumbing fixture，原 F1 断言不删除、不跳过。新 P2 测试的成功命令 DTO **没有启动任何子进程**，只测状态/接线；既有 P1 集成 runner 才包含真实 PowerShell 子进程执行，二者都不证明真实 DSH OS 沙箱。

真实 Reviewer 的[正/反候选准备说明](<../tests/live-probe-p2/README.md>)已经提供，但未调用模型，未安装/启动隔离 Host。后续范围、命令、预算、停止条件见[执行授权计划](<../docs/P2-EXECUTION-PLAN.md>)；当前仅允许提交开发报告，不能借“继续任务”自动运行检查。

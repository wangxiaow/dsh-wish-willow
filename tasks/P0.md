# P0 任务契约

来源：本次用户明确授权，仅实施 P0；完成后停止，未经验收不进入 P1。

## 最小方案
1. 独立 Git 仓库、单 npm Bundle、一条唯一命名的 Host/Client 插件行。
2. 使用已核实的 Cordis apply/inject、dsh.bundle.patch、dsh.client 和根级 settings.section Slot；不改核心、不新建服务器或 iframe。
3. 产品表存于 DSH Storage Domain `wish_willow`，与 Session 完全分离。P0 只维护 ID、名称、愿望文本、手动状态、revision、时间戳；不创建 Agent/任务/执行状态。
4. 复用 Typert Gateway 与 Connection 的跨载体 RPC。普通 JavaScript 通过公开 Remote 标准装饰器的调用形式暴露方法，采用官方文档描述的 SRC 回退；业务入口自行严格 Zod 校验。严格生成式 Remote 留待后续 API 稳定后评估，不虚构生成器已验证。
5. 全部读写返回副本。更新在 DSH domain.table.update 写队列内部比较 revision；拒绝冲突，不静默覆盖。
6. 使用 DSH JSON 后端，复用原子发布与持久写入；不用聊天历史、LocalStorage 或自写文件数据库。

## 验收条件
- Bundle 格式、安装包内容、运行时激活与 Client Slot 注册分别检查。
- 创建、读取、更新、错误输入、并发冲突、持久写失败、坏数据/版本拒绝、卸载释放有自动化测试。
- 使用真实 Cordis + Storage Domain + JSON + Gateway；两个独立 Node 进程验证恢复，不把这等同于完整 Desktop 重启。
- Web/原生 Desktop 分别记录证据；没有实际操作/截图的项目标记未验证。
- 当前 Desktop 启动的 Host 不由本任务强制停止，避免中断用户会话。完整应用重启按手工验收步骤补充。
- GitHub 安装格式有官方依据；没有远程仓库、不擅自推送，不声称远程 URL 已安装。

## 边界与风险
- Host 插件在 DSH 主进程权限范围运行，安装改变当前 profile 全部会话。没有 shell、模型、网络业务调用或新凭据权限。
- JSON 后端没有跨进程写锁：同一 DSH storage root 只能有一个写入 Host。P0 不重造锁基础设施。
- 启用/停用保留数据，无删除接口；不支持迁移，坏数据失败关闭而非重置。
- 源码与官方 README 来自本机 0.2.0-rc.2 ASAR 的只读副本。GitHub fetch 被工具 DNS 检查拒绝；不绕过该检查。原仓库 docs/PRD.md、docs/ARCHITECTURE.md、tasks/P0.md 均不存在，本次才创建最小阶段文档。

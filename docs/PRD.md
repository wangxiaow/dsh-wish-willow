# Wish Willow：已授权需求摘要

来源：用户明确需求和阶段授权，不把长期设想扩展成当前工作。

最终愿景是许愿式软件创造：人表达愿望与重大决策，Agent 承担常规软件工程；复用原版 DSH 插件机制，产品事实独立于执行 Session。

- P0 已于 2026-10-10 正式验收关闭。P0 手动状态不表示 Agent 在执行；用户表单愿望是用户确认事实，不将模型推断标记为确认。
- P1 经 P1-A/B/C、统一 Bundle 与 F1 收敛后，按[关闭记录](<P1-CLOSURE-0.3.2.md>) 为 **CLOSED WITH ACCEPTED EXCEPTION**。0.3.2 未公开发布，真实成功 DSH 交付的 `EX-P1-032-01` 仍 NOT VERIFIED，不能用 P2 代码补写为解决。
- 用户现已批准[ P2 任务契约](<../tasks/P2.md>)：先保全 P1，再增量开发独立 Reviewer、必要测试证据、确定性三级 Host 门禁、可选持久质量历史及统一工作台的最小展示/操作。
- **当前仅授权源码/测试/技术文档写入与只读静态查看。** 测试、build、pack、安装、隔离运行、真实模型、Git 提交/推送/发布另行批准，见[执行计划](<P2-EXECUTION-PLAN.md>)。P2 未验收关闭；不进入 P3，不重开 P1，不修改 DSH/ACL 来消除既有例外。

## P2 必须满足

1. 一个原版 DSH 独立 Bundle、一个 Client；保留既有 Domain/单写入 Host，不建设新 Agent 框架、通用安全平台或多模型调度。
2. Coder 停止写入、候选固定后才创建独立的 fresh Reviewer Session，不能继承/fork 编码对话。相同默认模型允许，但必须实读受限的实际源码/测试/差异/证据，不以 Coder 自述或 exit 0 代替审查。
3. Reviewer 只读、审批 never；工具层拒绝 Shell/写入/网络/其他 Agent/审批/Release/越界。有限步骤与时间、不自动重试；同一候选最多一次用户显式重审，历史只追加。
4. PASS/FAIL/BLOCKED/UNVERIFIED 明确区分。必要材料未读完、证据/身份/会话/报告不完整或模型/环境失败均不能 PASS。
5. 低风险须证明仅非执行性说明变更；首发和功能/测试/配置/入口默认中风险；重大决策、敏感权限/隐私/凭据、破坏性操作、外部发布意图为高风险。Reviewer 只能提风险，不能降低 Host 下限。
6. 低/中风险 PASS 才释放；高风险还需明确绑定本候选/最新审查/风险/本地交付范围的用户批准。批准不授予破坏性行为、权限修改或公开发布权。
7. 新增 Release 的最终门禁在 Host 状态层，重验物理 hash/关联、CAS/幂等、拒绝普通 mutate 旁路。待批准候选可重开后继续，不重跑 Coder；旧状态可读、不补造旧审查、不静默丢弃降级不兼容字段。
8. 当前候选/当前版本/当前测试和独立审查不可被旧成功 Release 掩盖；用户可查看问题、依据和历史，并进行候选绑定操作。

开发自审与脚本化 fixture 不替代独立验收。P2 真实验收限于另行授权的一例小型正确候选和一例刻意缺陷候选；不重做 P1 闭环，也不扩大语言/框架支持承诺。

# 🌿 Wish Willow · 许愿柳

**用自然语言表达愿望，让软件有目标、有记忆、可持续演化。**

基于 **DeepSeek Harness（DSH）** 的独立插件。<br>
你负责表达需求、做重要决定与体验软件；Agent 负责具体工程，许愿柳负责保存产品状态与交付依据。

## 什么是许愿柳？

许愿柳围绕“表达愿望 → 开发软件 → 验证结果 → 使用反馈 → 继续修改”组织软件创造与演化。

它不是另一个必须使用的聊天框。你可以在 DSH 原生对话中表达软件目标、提出修改意见和决定重要事项；许愿柳在后台关联愿望、任务、版本与证据，让一次次对话围绕同一个产品持续推进。

## 核心理念

- **愿望是起点**：用自己的语言描述要解决的问题，不必先把想法写成技术方案。
- **产品有独立记忆**：区分已确认需求与 Agent 推断，保留目标、约束、决策和变更记录，不把聊天历史当作唯一依据。
- **工程交给 Agent**：复用 DSH 的模型、会话、工具与执行能力，不额外搭建一套开发底座。
- **结果需要证据**：生成代码、测试通过、审查通过和实际交付是不同的事；失败和未知不能包装成成功。
- **修改不抹去过去**：通过版本和源码快照保留交付依据，让新愿望与既有产品建立联系。
- **重要决定由你掌握**：重大方案、敏感权限和外部操作不能仅凭 Agent 自行判断放行。

## 怎样使用？

1. 在 DSH 中启用许愿柳，并配置你要使用的模型与工程工作区。
2. 在原生创造模式对话中，描述你想要的软件或希望修改的地方。
3. 根据提示确认重要事项；需要时，通过许愿柳工作台查看产品状态、任务、版本和证据。
4. 按实际交付的启动方式运行软件，亲自体验，再通过原生对话提出下一次修改。

许愿柳工作台用于监督、决策与兼容操作，不应成为重复输入同一愿望的必经步骤。软件是否可用，应以实际运行与使用体验为准。

## 适合哪些场景？

- 把一个具体的软件想法逐步变成可体验的本地工具。
- 围绕同一产品进行多轮需求修改与版本演化。
- 需要保留“为什么这样做、实际验证了什么、交付对应哪个版本”的个人项目。

许愿柳不承诺任意技术栈的无人值守开发，也不把自动重试等同于可靠恢复。公网部署、付费服务和破坏性操作仍需单独确认。

## 数据与使用边界

产品状态独立于聊天会话保存。备份时应同时考虑产品记录、项目源码和版本资产；只有聊天记录不足以恢复整个软件。

模型调用、文件修改和命令执行通过 DSH 的能力与授权机制进行，可能产生模型费用或本地副作用。请核对执行范围，不要在公开问题、截图或日志中提供密钥、认证链接或私人会话。
